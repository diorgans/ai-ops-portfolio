Setup — your steps, in detail

Everything that could be built for you is built. These are the parts that need your accounts.

About 25 minutes. Steps 2–3 are HubSpot admin, 4–8 are n8n.

1. Start n8n

Double-click start-n8n.bat in the project folder.

Wait for "Editor is now accessible via http://localhost:5678" — about a minute on first run. Leave that console window open; closing it stops n8n.

Open http://localhost:5678 and create the owner account if asked. It's local only.

Seeing a "Failed to start Python task runner" message and a list of deprecation warnings is normal. The line that matters is Registered runner "JS Task Runner" — that's the one the workflow needs. If n8n offers to configure a sandbox service asking for a URL and API key: skip it. It needs Docker and is optional.

2. HubSpot — create a Service Key

HubSpot changed this in late 2026. Private apps were consolidated into a "Legacy Apps" page and then removed for newer accounts. The replacement for "I just want a token to call the API from my own code" is a Service Key. If your account offers Legacy Apps, that still works; if it says "Legacy apps aren't available on this account", use a Service Key as below. Service Keys are the right fit here: they're for data-only, system-to-system access, which is exactly what this workflow does. They don't support webhooks or UI extensions — we don't need either. The alternative, a project-based app, needs the HubSpot CLI and is far more setup than this warrants.
  1. Go to https://app.hubspot.com and log in.
  2. Click the gear icon ⚙ in the top-right of the blue navigation bar.
  3. In the left sidebar go to Integrations → Service Keys.
  • Depending on the account, it may sit under a Development section instead.
  • Fastest route either way: the search box at the top of the settings sidebar — type

service.

  1. Click Create a service key.
  2. Give it a name: Lead Triage.
  3. Add scopes. Search for contacts and select:
  • crm.objects.contacts.read
  • crm.objects.contacts.write

Grant only these two. Least privilege — a key that can only read and write contacts can't do damage elsewhere if it leaks.

  1. Review, then Create.
  2. Copy the key immediately and paste it into Notepad. HubSpot may not show it again.
Needs Super Admin or Developer tools access. On your own developer account you have it. If the key is ever exposed, there's a Rotate button — use that rather than deleting and rebuilding the integration.

Sources: Service Keys announcement · Legacy private apps · Developer platform overview

3. HubSpot — add two contact properties

The workflow writes the tier onto the contact record, so the fields have to exist first.

  1. Still in Settings (⚙).
  2. Left sidebar → Data Management → Properties.
  • Or type properties in that sidebar search box.
  1. At the top there's a dropdown reading "Select an object". Choose Contact properties.
  2. Click Create property (top right).
  3. Fill in:
fieldvalue
Object typeContact
GroupContact information (any group is fine)
LabelLead Triage Tier
  1. Check the internal name. Under the Label box there's small grey text showing the internal

name HubSpot generated, with an edit (pencil) icon. It must read exactly:

`` lead_triage_tier ``

If it reads anything else, click the pencil and correct it. This is the one thing that must match exactly — it's what the API writes to.

  1. Click Next. For Field type choose Single-line text.
  2. Click Create.

Now repeat steps 4–8 for the second property:

fieldvalue
LabelLead Triage Reason
Internal namelead_triage_reason
Field typeSingle-line text

4. n8n — create two credentials

n8n stores secrets separately from workflows, which is why importing the workflow doesn't bring them along.

  1. In n8n, find Credentials in the left sidebar. In this version it may be a tab at the top

of the Overview page rather than its own sidebar item — look for Workflows | Credentials | Executions.

  1. Click Add credential (or Create Credential).
  2. In the search box type Header Auth and pick Header Auth.

Credential one — Anthropic:

fieldvalue
Namex-api-key
Valueyour Anthropic key — it's in C:\Users\nchen\Downloads\lead-triage\.anthropic_key

Rename the credential itself to Anthropic API — click the credential's title at the top of the dialog (it'll say something like Header Auth account) and type over it. Click Save.

Credential two — HubSpot: repeat, new Header Auth credential:

fieldvalue
NameAuthorization
ValueBearer <your service key>

The value is the literal word Bearer, then one space, then the Service Key from step 2. Rename the credential to HubSpot Private App (the workflow expects that name) and Save.

Service Keys authenticate exactly like the old private-app tokens — same Authorization: Bearer header — so nothing else in the workflow changes.
Open .anthropic_key with Notepad to copy the key. Don't paste either secret into a chat window or a file in the repo.

5. n8n — import the workflow

  1. Left sidebar → Workflows → Create Workflow (this opens a blank canvas).
  2. In the top-right of the canvas, click the ⋯ (three dots) menu.
  3. Choose Import from File…
  4. Select:

`` C:\Users\nchen\Downloads\lead-triage\workflows\lead-triage.json ``

Five nodes should appear, left to right:


Webhook → Claude — extract facts → Apply rubric (code) → HubSpot — create contact → Respond

Press Ctrl+S to save. Name it anything.

6. n8n — attach the credentials to the nodes

Two nodes need a credential selected. Importing never carries secrets.

  1. Double-click the node Claude — extract facts.
  2. Near the top there's Credential for Header Auth with a dropdown. Choose Anthropic API.
  3. Close the node (click the canvas, or Back to canvas top-left).
  4. Double-click HubSpot — create contact.
  5. Same dropdown → choose HubSpot Private App.
  6. Close it, then Ctrl+S to save.

7. Test it

  1. In n8n, click Test workflow at the bottom of the canvas. It now waits for one request.
  2. In Explorer, right-click test-webhook.ps1 → Run with PowerShell.
  3. The script pauses and tells you to press Enter — press it. It sends the first lead.
  4. Watch the n8n canvas: each node should turn green in turn.
  5. The script prints the response.

Expected first result — tier D:


{ "tier": "D", "reason": "Rule 1 — job seeker overrides fit.", "facts": { "disqualifier": "job_seeker", ... } }

That's a support team lead at an ideal customer — and the correct answer is still D, because he's asking for a job. That's the whole point of the project.

  1. The script then waits again. Click "Test workflow" in n8n once more (it only listens for one

request at a time), then press Enter in the script window.

Expected second result — tier A: same company, a VP with budget and a three-week deadline.

  1. Check HubSpot: Contacts → you should see both people, with Lead Triage Tier set to D

and A. If the column isn't shown, use Edit columns to add it.

8. Activate — optional

Toggle Active in the top right to make the webhook live at http://localhost:5678/webhook/lead-triage — note /webhook/, not /webhook-test/.

Only useful if something real is posting to it. For a demo video, Test workflow is better anyway: it animates each node as data flows through, which shows the architecture on screen.
